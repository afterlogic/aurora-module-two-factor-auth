# TwoFactorAuth mobile — E2E tests

Playwright specs for the Authenticator-App 2FA flows in the mobile UI
(`?mobile-version`). Discovered automatically by the runner in
`CoreMobileWebclient/vue-mobile` — see that package's `test/e2e/README.md` for
setup (`.env.e2e`, browsers, `npm run test:e2e`).

```bash
# from modules/CoreMobileWebclient/vue-mobile
npm run test:e2e -- --setup "TwoFactorAuth iPhone13"
```

Requires a running Aurora stand **with this build deployed** and
`E2E_LOGIN` / `E2E_PASSWORD` for a normal user. `AllowAuthenticatorApp` is on by
default; specs `test.skip` themselves when the 2FA settings tab is absent.

## Specs (`two-factor-auth.spec.js`)

| Test | What it does | Mutates account? |
|------|--------------|------------------|
| settings: configuration dialog appears | Settings → 2FA tab → confirm password → asserts QR + secret + code field | no |
| settings: full setup with a computed TOTP code | Reads the secret from `RegisterAuthenticatorAppBegin`, submits a code generated by `helpers/totp.js`, asserts the backend reports it enabled | yes — reverted in the test + `afterEach` |
| login: mandatory setup dialog | Only runs if the stand sets `MandatoryToConfigure`; otherwise skips | no |

## Teardown

`afterEach` calls `TwoFactorAuth/DisableAuthenticatorApp` through the app's own
session (`helpers/two-factor.js → callAppApi`), never through the admin UI. It is
a no-op when nothing was enabled and never fails the run.
